# GitHub Actions mobile and macOS build corrections

This update is based on the latest uploaded KaalKey source and the supplied GitHub Actions logs.

## Android APK and AAB signing

The previous workflow restored the keystore and configured Gradle signing, but the signing secrets were only present in the `Configure release signing` step. The generated Gradle configuration reads those values from the process environment when Gradle actually runs. The `Build signed APK and AAB` step now explicitly receives `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`; `ANDROID_KEYSTORE_FILE` continues to come from `GITHUB_ENV`. The build step checks that all required values are present before starting Gradle.

No keystore or password is regenerated. Continue using the four existing GitHub Actions secrets.

## iOS Simulator build output

The previous workflow searched only one exact Xcode output directory and only at its top level. The Simulator build step now searches recursively under the selected DerivedData `Build/Products` directory, prints discovered app bundles for diagnostics, and reports a clear error if no `.app` is found. It verifies the resulting ZIP before proceeding to the archive job.

The unsigned iOS archive remains a separate `xcodebuild archive` operation with code signing disabled.

## macOS desktop builds

The previous workflow attempted to merge Intel and Apple Silicon Electron apps into a universal app. Electron Builder failed while merging architecture-specific native Node modules such as `lightningcss.darwin-arm64.node`.

The workflow now builds each architecture natively in a separate GitHub-hosted runner:

- Intel x64: `macos-15-intel`
- Apple Silicon arm64: `macos-15`

Each job produces a DMG and ZIP with architecture-specific filenames. The release job downloads and attaches all four artifacts. This avoids the universal merge step rather than excluding native modules that the app might need.

The Electron Builder macOS icon is explicitly set to the ICNS file generated by the workflow.

## Validation and remaining verification

The workflow YAML and package JSON are syntax-checked, and the archive is checked for integrity. The local environment cannot run Xcode or GitHub-hosted builds, so successful compilation and signing still need confirmation from the next GitHub Actions run.
